# 사용자 좋아요와 MMS 컬렉션

## 변경 이유

기존 MMS의 저장 트랙·가져온 플레이리스트와 별개로, 사용자가 검색·GMS·EMS에서 마음에 든 트랙·플레이리스트·앨범·아티스트를 직접 표시하고 한곳에서 관리할 수 있어야 했다. GMS의 추천 수락은 취향 모델 입력이므로 영구 좋아요와 분리할 필요도 있었다.

## 변경 내용

- PostgreSQL에 사용자별 `user_likes` 테이블을 추가했다. 식별 키는 `(user_id, entity_type, source, source_id)`이며 유형은 `track`, `playlist`, `album`, `artist`, 출처는 `tidal`, `catalog`로 제한한다.
- `GET /api/likes`, `PUT /api/likes/{entityType}/{source}/{sourceId}`, `DELETE /api/likes/{entityType}/{source}/{sourceId}`를 추가했다. 모든 조회·추가·삭제는 Auth0 subject로 현재 사용자 범위를 제한하고 PUT snapshot은 16 KiB를 넘으면 DB 접근 전에 거부한다.
- root layout이 로그인 사용자의 좋아요를 한 번 읽어 `LikesProvider`에 전달한다. 공통 `LikeButton`은 낙관적으로 화면을 갱신하고, 같은 항목의 중복 요청을 잠그며, 실패하면 이전 상태를 복구한다.
- 검색에 아티스트 결과와 아티스트 탭을 추가하고 통합 결과·트랙·앨범·플레이리스트·아티스트에 독립 하트 버튼을 배치했다.
- EMS와 공통 트랙 목록, GMS 트랙 카드에 하트를 추가했다. 재생 불가 트랙도 좋아요할 수 있으며 하트 선택은 재생·상세 열기·추천 액션을 실행하지 않는다.
- GMS의 기존 `좋아요` 추천 결정을 `추천 수락`으로 바꾸고 영구 좋아요 하트와 구분했다.
- MMS의 페이지 제목은 `My Music Space`로 유지하고 좋아요는 그 안의 부속 컬렉션으로 구성한다. 저장 트랙 박스는 제거하되 TIDAL에서 가져온 플레이리스트 카드를 유지하며, 본문은 `가져온 플레이리스트` 다음에 `좋아요한 트랙`, `좋아요한 플레이리스트`, `좋아요한 앨범`, `좋아요한 아티스트`를 표시한다.
- 가져온 플레이리스트 카드는 DB에 저장된 수록곡으로 상세·전체 재생·셔플을 제공하고, 플레이리스트 자체를 좋아요할 수 있다.
- TIDAL 플레이리스트·앨범 좋아요는 기존 catalog API로 상세 트랙을 조회해 전체 재생과 셔플을 제공한다. 좋아요 해제는 같은 전역 상태를 통해 카드·개수·빈 상태에 즉시 반영된다.
- 좋아요는 플레이리스트 가져오기, MMS의 기존 저장 데이터, GMS 추천 수락·싫어요와 별도로 저장한다. 기존 데이터는 삭제하거나 자동 좋아요로 변환하지 않았다.
- 역변경용 `005_user_likes.down.sql`을 함께 제공한다.

## DB 적용 결과

- `psql` 실행 파일이 설치되어 있지 않아 앱이 사용하는 `pg` 드라이버로 `005_user_likes.sql`을 동일하게 실행했다.
- 대상: 로컬 PostgreSQL `127.0.0.1:55434/music_pie`
- 적용 전 `public.user_likes`가 없는 것을 확인한 뒤 migration을 적용했다.
- 적용 후 11개 열, 기본 키 1개, 사용자 외래키 1개, 복합 고유 제약 1개, 유형·출처·길이 등을 포함한 CHECK 제약, `user_likes_user_created_idx`를 읽기 전용으로 확인했다.

## 검증 결과

- RED 단계에서 타입·DB·API·provider·버튼·트랙 UI·검색·MMS의 기존 동작이 새 요구를 충족하지 못하는 것을 각 집중 테스트로 확인했다.
- MMS 페이지·라이브러리·대시보드 집중 테스트: 3개 파일, 9개 테스트 통과
- 전체 `npm test`: 57개 파일, 210개 테스트 통과
- `npm run lint`: 통과
- `npm run build`: Next.js production build와 TypeScript 통과
- 새 production build로 44119 서버를 교체한 뒤 로컬·공개 `/search`, `/mms`가 모두 HTTP 200을 반환했다.
- 비로그인 `GET /api/likes`가 `401 {"code":"unauthorized"}`를 반환하는 것을 확인했다.
- 가져온 플레이리스트 복원 후 DB에서 플레이리스트 3개와 소속 트랙 101개가 존재하는 것을 읽기 전용으로 확인했고, 로컬·공개 `/mms`가 다시 HTTP 200을 반환했다.
- `My Music Space`를 유일한 페이지 `h1`로 유지하고 `내 좋아요`가 페이지 제목으로 노출되지 않는 회귀 테스트를 추가했다. 최종 production build 교체 후 로컬·공개 `/mms`가 모두 HTTP 200을 반환했다.

## 미검증·제약

- 기존 로그인 Chrome 탭에 대한 브라우저 자동 연결이 두 번 타임아웃되어 실제 계정으로 네 유형 하트를 누르고 MMS에 반영되는 수동 시각 검증은 완료하지 못했다.
- catalog 출처의 앨범·플레이리스트는 TIDAL catalog ID가 없으므로 MMS에서 상세 트랙 열기를 제공하지 않는다.
- fixture 기반 EMS/GMS 트랙은 TIDAL ID가 없으면 좋아요 저장은 가능하지만 실제 TIDAL 스트리밍 대상은 아니다.

2. `/mms`에서 네 유형의 개수·순서·해제 즉시 반영과 TIDAL 앨범·플레이리스트 전체 재생·셔플을 확인한다.
3. 로그아웃 상태의 하트가 현재 내부 경로를 `returnTo`로 포함해 로그인으로 이동하는지 확인한다.
