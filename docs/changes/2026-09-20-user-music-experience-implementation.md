# 사용자 음악 경험 초기 구현 기록

## 변경 이유

사용자가 EMS를 탐색하고, TIDAL 온보딩을 거쳐 개인 GMS·MMS에서 추천 행동을 할 수 있는 첫 사용자 화면 흐름이 필요했다.

## 변경 내용

- `apps/web`에 Next.js·TypeScript·Tailwind CSS·Vitest 기반 사용자 웹 앱을 추가했다.
- 비로그인 사용자는 EMS 공개 레일을 탐색·재생할 수 있고, 개인화 저장은 TIDAL 온보딩으로 안내한다.
- TIDAL 연결, 플레이리스트 선택, MMS 초기화의 3단계 온보딩과 빈·트랙 없음 플레이리스트 오류 상태를 추가했다.
- GMS 수락, MMS 추가, 사용자 단위 추천 제외, 되돌리기와 MMS 제외 관리 화면을 추가했다.
- 루트 고정 플레이어, 전체 화면 플레이어, 큐, 재생 위치 상태를 추가했다.

## 검증 결과

- 성공: `npm run test` — 6개 테스트 파일, 15개 테스트 통과
- 성공: `npm run lint`
- 성공: `npm run build`

## 미검증 및 다음 작업

- 실제 TIDAL 인증·플레이리스트 조회·재생은 권한 범위와 API 데이터 계약이 확인되지 않아 연결하지 않았다.
- 영구 추천 제외의 새로고침 이후 보존은 사용자별 데이터 보관 기간, 삭제·복구 정책, PostgreSQL 저장 계약이 정해지지 않아 구현하지 않았다. 현재 상태는 브라우저 세션에 한정된다.
- 정책이 확정되면 사용자 식별자를 경계로 한 서버 저장소와 제외 상태 복원 회귀 테스트를 추가한다.
