# 관리자·일반 회원 접근 분리

## 이유

관리자 API에는 Auth0 `sub` 허용 목록 검사가 있었지만 `/admin` 화면 자체는 비로그인 방문자에게도 제공됐다. 회원 화면에는 관리자로 이동하는 메뉴가 없었고, 관리자 템플릿의 로그인·로그아웃 메뉴는 실제 Auth0 세션과 연결되지 않았다.

## 변경

- 공통 Auth0 세션과 `ADMIN_AUTH0_SUBJECTS`로 관리자 화면·API 권한을 판별한다. 비로그인 `/admin/*`은 Auth0 로그인으로 보내고 원래 관리자 경로로 돌아오게 한다. 로그인한 일반 회원에게는 404를 반환해 관리자 앱을 렌더링하지 않는다. 관리자 API의 기존 401/403은 유지한다.
- 회원 화면은 관리자로 로그인했을 때만 `관리자` 링크를 표시한다. 관리자는 회원 화면도 계속 사용할 수 있다.
- 관리자 프로필 메뉴를 실제 회원 화면·Auth0 로그아웃 경로에 연결하고, 사용하지 않는 템플릿 로그인·회원가입 화면 진입을 제거한다.
- DB 역할 스키마나 별도 Auth0 애플리케이션은 추가하지 않았다.

## 검증

- Admin/Web production build 통과. Admin 번들 크기 경고와 로컬 Auth0 환경 변수 경고는 기존과 같다.
- 변경 파일 ESLint 오류 0건, `git diff --check` 통과.
- 자동 테스트는 요청되지 않아 추가하거나 실행하지 않았다.

## 운영 적용·미검증

- `81af208`을 Zorin Web 이미지로 빌드해 Web 컨테이너만 교체했다. 이전 이미지는 `music-pie-web:pre-admin-member-20260925`로 보존했다. Web은 healthy, 공개 readiness는 HTTP 200이다.
- 공개 비로그인 `/admin`과 `/admin/ems/ingestion`은 각각 원래 경로를 `returnTo`로 전달하는 Auth0 로그인 주소로 HTTP 307 이동한다. 비로그인 `/api/admin/ems/summary`는 HTTP 401이다.
- 로그인된 관리자 브라우저에서 `/admin/ems/ingestion`의 실제 수집 현황이 보였고, 회원 홈에서도 `관리자` 링크와 회원 음악 화면이 함께 표시됐다.
- 허용 목록에 없는 실제 로그인 계정으로 404 화면을 직접 확인하는 작업은 별도 일반 회원 세션이 필요하다.
