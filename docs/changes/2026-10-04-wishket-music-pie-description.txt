Music Pie는 사용자의 TIDAL 플레이리스트와 음악에 대한 선호 액션을 바탕으로 취향을 분석하고, 새로운 음악을 추천하며, 좋아하는 음악을 나만의 라이브러리에 모으는 웹 플랫폼입니다. 기획·UI/UX·프론트엔드·백엔드·추천/분석 서비스·DB·배포·운영을 담당한 참여율 100% 개인 프로젝트입니다. 2026년 9~10월 핵심 기능을 구축하고 현재 공개 서비스 운영과 개선을 이어가고 있습니다.

서비스: https://mrms.approid.team/
GitHub: https://github.com/imorangepie20/mrms.approid.team

1. 세 가지 음악 공간과 발견 경험
EMS(External Music Space)는 외부에서 검증·수집한 음악 카탈로그, GMS(Gateway Music Space)는 사용자 취향에 맞춘 추천 공간, MMS(My Music Space)는 좋아하는 음악과 개인 플레이리스트를 보관하는 공간으로 설계했습니다. 홈의 인터랙티브 셰이더 히어로·이용 안내·편집 선곡·콘텐츠 카드에서 탐색과 추천, 보관으로 자연스럽게 이어집니다. 앨범 아트 중심 카드, 가로 레일 스크롤, 반응형 화면, 로딩·빈 상태·오류 안내를 구현했습니다.

2. 회원 인증·TIDAL 연결·온보딩
Auth0 회원 로그인과 관리자 접근을 분리하고 TIDAL OAuth 연결 및 전체 재생을 위한 Device Code 인증을 구성했습니다. 사용자가 허용한 플레이리스트를 선택해 가져오며 저장·메타데이터·취향 분석의 실제 진행 상태를 표시합니다. 연결 상태·만료·재승인·토큰 갱신·연결 해제를 처리하고, 카탈로그 인증과 재생 인증이 서로 덮어쓰이지 않도록 분리했습니다.

3. 음악 검색·상세 탐색·전역 재생
트랙·앨범·아티스트·플레이리스트 검색과 상세 탐색, 곡 재생·좋아요·개인 플레이리스트 추가를 제공합니다. 페이지 이동 중에도 전역 플레이어를 유지하고 큐·이전/다음·셔플·반복·재생 위치·볼륨·전체 플레이어를 연결했습니다. TIDAL FULL manifest를 서버에서 검증해 direct/HLS 스트림을 재생하며 HTMLAudioElement와 hls.js를 사용합니다. 계정 권한·구독·지역과 provider 재생 가능 상태에 따른 실패를 안내합니다.

4. MMS 개인 라이브러리
좋아요한 트랙·앨범·아티스트·플레이리스트, TIDAL에서 가져온 플레이리스트와 GMS에서 수락한 추천을 구분해 보관합니다. 내부 플레이리스트 생성·이름/설명 편집·삭제, 곡 추가·제거·순서 변경과 재생을 구현했습니다. 선호 트랙은 취향 프로필에 반영하며 앨범·아티스트·플레이리스트 보관 액션을 트랙 학습과 혼동하지 않습니다.

5. GMS 개인화 추천·결정·이력
사용자별 취향 벡터와 활성 EMS 후보를 사용해 유사도·카탈로그 신뢰도·발매 최근성·편집 우선순위를 조합하고 아티스트 다양성을 고려합니다. +MMS 수락·스킵·싫어요를 저장하며 수락곡은 MMS에 반영하고 좋아하지 않는 곡은 해당 사용자의 이후 추천에서 영구 제외합니다. 다른 사용자나 EMS 원본에는 이 제외를 적용하지 않습니다. 제공된 곡은 액션이 없어도 사용자별 노출 이력에 기록해 중복 추천을 방지합니다. 새로고침에서는 같은 추천 배치를 유지하고 명시적인 다시 추천 요청으로 새 배치를 생성합니다. 추천 이력의 개별/전체 체크박스·선택 삭제, 커스텀 확인창과 성공 알림을 구현했습니다. 화면에서 이력을 숨겨도 추천 중복 방지 기록은 보존합니다.

6. 텍스트 취향 모델과 군집 분석
곡명·아티스트·앨범·MusicBrainz 장르/태그를 다국어 Sentence Transformers 모델의 768차원 L2 정규화 벡터로 변환합니다. 중복 플레이리스트 소속·아티스트 편중·좋아요/수락 가중치를 반영해 사용자 중심 벡터를 계산하고 충분한 입력에서는 spherical K-means와 품질 조건으로 취향 군집을 구분합니다. 입력 수·처리 성공/실패·coverage·모델 revision·입력 hash·프로필 version을 추적하고 PostgreSQL/pgvector로 유사도 검색을 수행합니다.

7. 30초 프리뷰 오디오 분석과 안전한 하이브리드
별도 FastAPI 서비스가 FFmpeg로 오디오 형식·길이를 검증하고 30초 프리뷰를 분석합니다. Essentia DSP의 리듬·에너지·음색·화성 특징, MAEST 2,304차원 오디오 임베딩과 MusiCNN 계열 분위기/보컬 예측을 추출하며 ONNX Runtime을 활용합니다. 10초 3구간과 전체 구간, 모델/특징 버전·hash·coverage를 구분해 저장합니다. 원본 오디오와 signed URL을 영구 보관하지 않습니다. 텍스트·오디오·분위기·리듬을 결합하는 하이브리드는 제한 사용자에서 필요한 component가 모두 완성된 경우에만 제공하고, 미달이면 텍스트 기반 추천으로 돌아갑니다. 비교용 shadow ranking과 실제 추천 provenance를 남기며 전 사용자 적용이나 정확도 향상률을 과장하지 않습니다.

8. EMS 수집·정합성·출처 추적
TIDAL 편집 플레이리스트·외부 음악 소스 후보를 기존 카탈로그와 연결하고 ISRC/TIDAL ID 중복, 활성 상태, 한국 STREAM 재생 가능과 최소 길이를 검증합니다. MusicBrainz 메타데이터 보강과 임베딩 처리, 수집 출처·시각·점수·상태를 관리합니다. 멜론은 5곡 묶음으로 8장르를 순환하고 장르별 커서를 저장해 발라드에 치우치지 않도록 개선했습니다. 작업별 대기·진행·완료·실패·재시도·heartbeat와 요청 budget·timeout·lease를 관리합니다. 허용 공개 URL의 후보 추출·검토·승인/제외 경로도 구현했으며 이 경로의 운영 실수집 검증은 별도 범위입니다.

9. 관리자 운영 도구와 선곡 갱신
HUD 기반 관리자에서 카탈로그·수집 작업·멜론·소스 루틴·통계·취향/오디오 분석 현황을 조회합니다. 홈과 EMS의 제목·설명·순서·노출을 독립 관리하고 홈 히어로·안내·스토리 콘텐츠를 편집합니다. 공통 선곡은 기준 설명 → 비동기 미리보기 → 섹션별 추가/제외·곡·원본 확인 → 커스텀 확인 후 적용으로 갱신합니다. 현재 노출 밖 적격 후보를 우선하고 부족하면 기존 곡으로 채웁니다. 만료·기존 목록 변경·재생 불가·동시 적용을 검증하고 5개 섹션을 단일 transaction으로 교체해 부분 실패를 막습니다.

실제 운영 메뉴는 EMS Overview(활성 트랙·카테고리·artwork 누락·임베딩·수집 상태), EMS(Tracks, 태그·시기 통계, Ingestion, 멜론 K-pop 수집, 공개 URL 수집, Spotify 차트, 정기 수집), 화면 관리(메인 화면·EMS 화면), 추천·취향(취향 분석 설계·오디오 분석 관측)의 네 그룹입니다. Spotify 공개 차트의 후보를 TIDAL 카탈로그와 연결해 한국에서 재생 가능한 곡을 공개 목록에 노출하고 차트별 확보 곡 수·출처를 제공합니다.

10. 운영·보안·품질
사용자 웹(Next.js 16/React 19), 관리자(React 18/Vite), Python 분석·수집 서비스와 PostgreSQL/pgvector를 Docker Compose로 분리해 Linux/Zorin 환경과 Cloudflare Tunnel에서 운영합니다. TypeScript·Tailwind CSS·FastAPI·PyTorch·Sentence Transformers·Essentia·ONNX Runtime·FFmpeg를 사용했습니다. 서버 측 토큰 암호화, 사용자별 데이터/권한 경계, 관리자 인증·same-origin 검사, 허용 URL/리다이렉트 제한, private network·resource limit·헬스체크와 readiness를 구성했습니다. Git release·DB migration·backup 검증·rollback 이미지로 변경을 추적합니다.

검증 사례: 2026-10-03 개선에서 Python 116개·관련 Web 41개·Admin 13개 테스트, 격리 PostgreSQL 적용/rollback/동시성 검증 11개 묶음과 두 앱 타입/lint/build를 통과했습니다. 운영 관리자 버튼으로 홈 36곡 중 29곡·EMS 60곡 중 52곡을 교체했고 실제 화면/API 순서가 저장 미리보기와 일치함을 확인했습니다. 화면별 설정·사용자 데이터·비대상 membership을 보존하고 기존 멜론 수집의 heartbeat 진전도 확인했습니다. 수락→MMS 반영·다시 조회 유지, 모바일/키보드와 커스텀 확인 취소 등 실제 사용 흐름을 검증하며 운영 오류 경계와 문서를 함께 관리했습니다.
