# TIDAL 검색 상세 요청 제한 제거

## 변경 이유

실제 계정으로 20곡을 검색할 때 각 트랙의 앨범·아티스트·커버 정보를 다시 조회해 TIDAL 상세 API 요청 20건이 발생했다. 이 중 7건이 `429`와 `Retry-After: 4`를 반환해 앱 검색 API가 `503`으로 종료됐다.

## 변경 내용

- `searchResults` 요청의 `include`에 트랙의 앨범·아티스트·앨범 커버 관계를 추가했다.
- 초기 검색 응답만으로 메타데이터가 완성되면 추가 트랙 상세 요청을 보내지 않는 회귀 검증을 추가했다.
- 실제 응답에서는 트랙 참조 72개 중 52개의 관계가 일부 누락돼 상세 요청이 다시 대량 발생했다.
- 검색 결과는 초기 `searchResults` 응답만으로 정규화하고, 누락된 앨범·아티스트·커버는 기존 기본값으로 표시하도록 변경했다. 검색 중 트랙별 상세 요청은 더 이상 보내지 않는다.

## 검증 결과

- 수정 전 회귀 테스트가 기존 `include` 값 때문에 실패하는 것을 확인했다.
- `npm test -- src/lib/tidal/search.test.ts`: 5개 테스트 통과
- `npm test`: 119개 테스트 통과
- Playwright 실제 계정 검색: `/api/tidal/search?q=Daft%20Punk` `200`, 결과 20곡, 실패 요청 0건
- 수정 전 회귀 테스트에서 두 번째 상세 요청이 발생해 실패하는 것을 확인했다.
- 수정 후 검색 adapter·컴포넌트 테스트: 7개 통과
- production 재빌드 후 공개 도메인 실제 검색: `Daft Punk` 결과 정상 표시
- Playwright 탭 검증: 트랙 표 1개와 헤더 5개, 앨범 카드 26개, 플레이리스트 카드 20개

## 미검증 항목

- TIDAL 초기 검색 응답에 관계가 없는 항목은 앨범·아티스트 기본값과 빈 커버로 표시된다.

## 다음 작업

- 메타데이터 보강이 필요하면 검색 요청과 분리된 지연 로딩 또는 서버 캐시 방식으로 설계한다.
