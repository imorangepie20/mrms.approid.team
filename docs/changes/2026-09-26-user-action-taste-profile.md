# 사용자 액션 취향 프로필 반영

## 변경 이유와 범위

사용자 트랙 좋아요와 GMS 추천 수락·거절은 저장됐지만 프로필 계산 입력에는 사용되지 않았다. 플레이리스트 기반 기준선을 유지하면서, 이미 EMS 임베딩이 완료된 TIDAL 트랙의 사용자 액션을 해당 사용자 프로필에만 연결했다.

## 변경 내용

- 프로필 입력 로더가 기존 선택 플레이리스트 트랙과 사용자가 좋아요한 TIDAL 트랙, 추천 수락한 EMS 트랙의 완료 임베딩을 합친다.
- TIDAL ID가 같은 플레이리스트 트랙과 EMS 트랙은 같은 EMS ID로 정규화해 중복 입력하지 않는다.
- EMS나 사용자 라이브러리 임베딩에 아직 없는 TIDAL 트랙 좋아요는 저장된 곡명·아티스트·앨범 스냅샷을 기존 임베딩 서비스에 전달해 프로필 계산 중 임시로 임베딩한다. 이 추가 벡터는 DB에 저장하지 않으며 다음 계산 때 다시 만든다.
- 좋아요 또는 추천 수락이 있는 고유 트랙은 플레이리스트·아티스트 기준 기본 가중치의 2배로 계산한다. 좋아요와 수락이 함께 있어도 중복 가산하지 않는다.
- 거절 이력이 있는 트랙은 좋아요나 수락 이력이 추가로 있어도 긍정 입력에서 제외한다. 기존 GMS 후보 쿼리의 수락·거절 영구 제외를 유지한다.
- 트랙 좋아요 추가·삭제, 추천 수락·거절을 저장한 뒤 프로필을 즉시 다시 계산한다. 스킵과 비트랙 좋아요는 프로필을 갱신하지 않는다.
- 사용자별 경로로만 좋아요 행을 읽고 계산하며, 좋아요 해제 뒤 재계산 입력에서 빠진다.
- 액션 저장은 완료됐지만 프로필 계산에 실패하면 API가 `taste_profile_refresh_failed`와 함께 액션 저장 완료 여부를 반환한다. 좋아요/결정 저장 실패와 프로필 계산 실패를 구분한다.

## 검증

- `apps/web`: `npm run build` — TypeScript와 production build 통과. 로컬 Auth0 환경변수 부재 경고가 있었다.
- `apps/web`: `npm run lint` — 오류 0개, 기존 경고 5개.
- 저장소: `git diff --check` — 통과.
- 자동화 테스트는 요청 범위에 따라 추가·실행하지 않았다.

## 미검증·배포 상태

- 2026-09-27 로그인된 운영 `/gms`에서 개인화 추천 12곡 표시를 확인했다. 같은 날 커밋 `c7a002d`를 `origin/codex/admin-url-ingestion`에 push하고 Zorin Web·EMS release로 배포했다. 이 기능은 DB migration을 요구하지 않는다. 배포 후 local/public readiness와 공개 `/gms`가 HTTP 200이었다.
- 실제 계정 데이터가 변경되는 좋아요·수락·거절 버튼은 누르지 않았다. 따라서 액션 저장 후 프로필 갱신과 거절 재추천 제외는 운영 브라우저에서 아직 확인하지 못했다.
