# 검색 추천어 실패 격리

## 변경 이유

검색 본문과 선택적 추천어 요청을 동시에 보내면서 추천어 API가 `4xx`·`5xx` 또는 네트워크 오류를 반환하면 정상적인 카탈로그 검색 결과까지 버려졌다. 이 경우 사용자에게 검색 자체가 고장난 것처럼 보였다.

## 변경 내용

- 카탈로그 검색 응답을 핵심 결과로 분리했다.
- 추천어 응답은 성공한 경우에만 반영하고, 실패·잘못된 JSON·취소는 빈 추천어로 처리한다.
- 카탈로그 검색 자체가 실패한 경우의 오류 표시는 기존 동작을 유지한다.
- 추천어 API 실패 중에도 트랙 결과가 표시되는 컴포넌트 회귀 테스트를 추가했다.

## 검증 결과

- `apps/web`: 검색·검색 API·검색 adapter focused Vitest 17개 통과
- `apps/web`: 전체 Vitest 84개 파일·340개 테스트 통과
- `apps/web`: `npm run lint` 오류 0 (기존 경고 3)
- `apps/web`: `npm run build` 및 TypeScript 통과

## 미검증 항목

- 로그인된 실제 브라우저의 TIDAL access token으로 공개 검색 결과를 다시 확인하는 절차는 배포 후 수행한다.
