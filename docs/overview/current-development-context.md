# 현재 개발 상태

최종 갱신: 2026-09-20

## 이번 목표

`docs/harness/portable-project-harness.md`의 내장 하네스를 적용한다. 루트 작업 규칙과 원칙·접근 순서·개요·작업 계획·변경 기록 문서를 준비하고, 각 참조 경로가 존재하는지 확인한다.

프로젝트 제품 목표는 TIDAL API로 사용자의 플레이리스트 트랙을 받아 사용자별 취향 모델을 학습하고 맞춤 음악을 추천하는 것이다. 추천 결과에 대한 사용자 액션은 해당 개인 모델을 계속 갱신하는 학습 근거가 된다.

## 현재 구현

- 프로젝트 하네스 적용 전에는 `docs/harness/portable-project-harness.md`만 존재했다.
- 루트 `AGENTS.md`와 하네스 필수 문서 6개를 추가했다.
- 수정된 하네스 안내에 맞춰 작업 계획·변경 기록 템플릿에 조사 근거, 직접 검증, 미정 항목을 기록하도록 보완했다.
- 제품 코드, 인증 구성, TIDAL API 연동은 아직 구현되지 않았다.
- TIDAL API 접근 권한은 확보된 것으로 본다. 실제 인증 범위와 응답 필드는 연동 전에 확인한다.
- 초기 개인화 추천 전략은 메타데이터 임베딩과 사용자별 취향 벡터의 액션 기반 갱신으로 확정했다.
- 사용자가 좋아하지 않음으로 확정한 트랙은 해당 사용자에게 영구 추천 제외한다.
- 관리자 프런트엔드는 제공된 `hud-admin-template`을 보존하는 React + Vite 기반으로 확정했다.
- 제품 코드, 런타임 설정, 테스트 명령과 배포 구성은 아직 확인되지 않았다.

## 미검증·제약

- 제품 코드와 실행 명령이 없어 빌드·테스트·UI·외부 연동은 검증하지 않았다.
- 기술 스택과 도메인 규칙은 후속 조사 전까지 미정이다.

## 다음 작업

1. TIDAL API의 실제 권한 범위와 플레이리스트·트랙 메타데이터 필드를 확인한다.
2. 사용자 액션의 종류·가중치와 영구 제외 취소·복구 정책을 정한다.
3. 추천 API와 화면의 입력·출력·성공 기준을 설계한다.
4. `hud-admin-template`의 복사 범위와 음악 추천 관리자 화면의 초기 기능을 정한다.
5. 작업마다 `docs/plans/task-template.md`와 `docs/changes/change-template.md`를 사용해 계획과 결과를 기록한다.
