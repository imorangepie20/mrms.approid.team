# 프로젝트 개요

- 프로젝트명: `music-pie`
- 목표: 사용자의 음악 취향을 분석해서 추천하는 웹 / 앱
- 사용자 역할과 핵심 업무: 타이달 유저, 타이달과 연결 플레이리스트를 가져와 음악취향을 분석하고 그에 맞게 추천받는다.
- 현재 웹 기술 스택: Next.js 16, React 19, TypeScript, Tailwind CSS, Auth0, PostgreSQL 클라이언트, TIDAL Web API와 `@tidal-music/player`.
- 계획된 별도 백엔드·인프라: PostgreSQL, FastAPI, Spring Boot, Tomcat, Zorin OS 홈서버. 실제 도입 전 구성과 버전을 확인한다.
- 관리자 템플릿 후보: `C:\Wspace\hud-admin-template`. 현재 사용자 웹은 `apps/web`의 Next.js 구현을 사용한다.
- TIDAL 검색·인증·재생 연동을 제공한다.

## 사용자 추천 로직 설계
### External Music Space / Gateway Music Space / My Music Space 로 구성됨
1. External Music Space - EMS : 외부 음악 중에서 현 시스템으로 도입된 트랙 / 플레이리스트 - 이 중에서 추천이 된다. 새로운 사용자의 플레이리스트도 이 곳으로 도입된다. 관리자 페이지에서 다양한 플렛폼에서 다양한 방법으로 트랙이나 플레이리스트를 도입할 수 있다.
2. Gateway Music Space - GMS : 특정 사용자에게 추천된 트랙이나 플레이리스트 공간으로 다양한 방법으로 사용자에게 노출된다. 사용자는 이곳에서 각 트랙을 듣거나 하여 선호 여부를 결정 할 수 있으며 My Music Space로 트랙이나 플레이리스트를 이동 시킨다. 
3. My Music Space - MMS : 사용자의 음악적 취향이 반영된 공간이다. 최초에는 사용자의 타이달 플레이리스트가 될 것이다. 사용자의 활동에 따라 AI 추천을 통해 플레이리스트가 추가되거나 삭제된다. 사용자가 GMS에 있는 트랙에 대해 선호 여부를 결정하면 해당 트랙은 MMS로 이동되고 , 좋아하지 않는다고 결정하면 MMS에서 영구적으로 삭제된다. 

### 영구 제외 규칙

- 사용자가 GMS의 트랙을 좋아하지 않음으로 결정하면, 해당 트랙은 그 사용자의 MMS에서 제거하고 이후 GMS 추천 후보에서도 영구 제외한다.
- 영구 제외는 사용자 단위로 적용한다. EMS 원본 카탈로그와 다른 사용자의 추천에는 영향을 주지 않는다.


## 사용자 화면 디자인
1. 고급스럽고 심플한 느낌으로 디자인 하되 컨덴츠가 비어 있는 느낌이 들어서는 안된다.
2. 트랙이 있는 어느 페이지에서도 플레이가 가능해야 하며 페이지 이동 시에도 유지 해야 한다.
3. 음악과 관련된 배경이미지를 충분히 활용한다. 앨범아트도 충분히 활용한다.
4. 메인 : 최신곡, 최신 플레이리스트, 추천곡, 추천플레이 리스트, 스트리밍 플랫폼 별 플레이 리스트 등으로 충분히 화면을 풍성하게 채운다.
