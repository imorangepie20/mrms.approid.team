# 사용자 액션 취향 프로필 반영 계획

- 날짜·작업명: 2026-09-26 사용자 액션 취향 프로필 반영
- 변경 이유: 트랙 좋아요와 GMS 수락·거절이 저장만 되고 취향 프로필 입력에는 반영되지 않는다.
- 범위: 완료된 EMS 임베딩과 연결 가능한 TIDAL 트랙 좋아요·추천 수락을 사용자별 프로필 입력에 추가하고, EMS 미매칭 TIDAL 트랙 좋아요는 저장된 스냅샷으로 즉석 임베딩한다. 액션 저장·삭제 후 프로필을 즉시 다시 계산한다. 거절 이력은 긍정 피드백에서 제외하며 기존 GMS 영구 후보 제외를 유지한다. 앨범·아티스트·플레이리스트 좋아요는 트랙 신호로 확장하지 않는다.
- 가중치: 플레이리스트 기반 기존 가중치는 유지한다. 하나 이상의 명시적 긍정 액션이 있는 트랙은 추가 입력에서 기본 트랙 가중치의 2배로 반영하며 같은 트랙의 좋아요·수락은 중복 가산하지 않는다.
- 변경 파일: `taste-profile.ts`, `taste-profiles.ts`, `embeddings/jobs.ts`, likes 및 recommendation decisions API 경로, 관련 계획·변경 기록·현재 개발 맥락.
- 검증: TypeScript/production build, ESLint, `git diff --check`. 자동화 테스트는 추가·실행하지 않는다.
- 완료 기준: 로그인 사용자의 TIDAL 트랙 좋아요 추가·삭제, 추천 수락·거절이 저장된 뒤 해당 사용자 프로필을 재계산하고, 거절 트랙이 긍정 액션으로 다시 들어오지 않는다. 비트랙 좋아요와 다른 사용자의 데이터는 영향받지 않는다. EMS 미매칭 좋아요 벡터는 DB에 보관하지 않고 매 계산 시 요청 메타데이터로 다시 만든다.
- 배포: 로컬 코드·문서만 변경한다. migration, 운영 데이터 갱신, 배포는 수행하지 않는다.
