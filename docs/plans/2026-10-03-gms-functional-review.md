# GMS 전체 기능 재점검

## 범위와 방법

- 요청: GMS 페이지의 모든 기능 재점검. `/gms`, `/gms/history`, 연결 API, 추천·프로필·재생·좋아요·내부 플레이리스트 경계를 포함한다.
- 저장소 기준: `4aabdd9`. 운영 브라우저는 현재 열린 Music Pie 세션을 사용한다.
- 실제 사용자에게 영구 노출·거절·이력 삭제를 남기는 조작은 자동 테스트와 격리 DB로 검증한다. 운영 브라우저에서는 표시·재생·탐색·반응형을 확인한다.
- 의존 순서: 설계·변경 기록 → 구현·테스트 목록 → 기능별 자동 검증 → 브라우저 → 결과 기록.

## 객관적 검증 체크

1. 접근·상태: 비회원, 연결 필요, 분석 미완료, 빈 후보, 오류 화면과 API 인증 경계를 관련 테스트로 검증한다.
2. 추천 제공: 사용자 격리, reject/exposure 제외, batch 유지·새 추천 멱등성·소진, hybrid full coverage fallback을 테스트한다.
3. 액션·분석: 수락·싫어요·좋아요·텍스트/오디오 분석의 성공·실패·중복 조작을 관련 UI/API 테스트로 검증한다.
4. 이력: 조회·페이지 이동·삭제 확인/취소·성공/실패·소유권·snapshot/exposure 보존을 관련 테스트로 검증한다.
5. DB 통합: 격리 pgvector PostgreSQL에 migration 적용 후 추천·프로필 통합 테스트를 실행한다.
6. 브라우저: 운영 GMS·이력 표시, 새로고침 유지, 재생·전역 player·목록 추가 메뉴와 console 오류를 확인한다.
7. 키보드·모바일: 접근 가능한 조작과 390×844 viewport에서 잘림·가로 overflow를 확인한다.
8. 정적·회귀: Web 전체 테스트, lint, production build, diff check를 실행한다.
9. MMS 연계: `+ MMS`로 수락한 트랙이 페이지 이동·새로고침 이후에도 MMS에서 조회되는지 사용자별 저장·조회 경로와 운영 화면을 대조한다.

## 완료 기준

모든 필수 체크가 PASS여야 전체 점검 완료로 보고한다. 첫 검증에 FAIL/UNVERIFIED가 3개 이상이면 원인 계층을 보고하고 증상별 수정을 중단한다. 2개 이하이면 원인을 해결한 후 전체 체크를 재검증한다. 실행 결과와 미검증 사유는 변경 기록에 남긴다.
