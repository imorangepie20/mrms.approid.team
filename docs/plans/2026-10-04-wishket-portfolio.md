# 위시켓 Music Pie 포트폴리오 추가

## 범위와 순서

- 사용자 요청: 기존 세 개 포트폴리오를 보존하고 Music Pie를 새 항목으로 추가한다. 운영 사이트와 GitHub 링크, 실제 기능·추천 기술·운영·검증·화면 자료를 충분히 담는다.
- 기존 항목: RESM — 부동산 매물·고객·계약 통합 관리 웹·데스크톱 앱 / 중소 유통업체 B2B 주문·재고·출고·정산 통합 시스템 / Alpha Momega — 부동산 임대·수납·시설 운영 통합 관리.
- 문서·코드와 실제 화면 대조 → 기능/기술별 근거 목록과 본문 작성 → 주요 화면 이미지 → 새 항목 입력 및 저장 → 재조회 순서로 진행한다.
- TIDAL 연결·온보딩·검색/상세/재생, MMS 보관, GMS 추천·피드백/영구 제외/이력, EMS 수집, 텍스트/오디오 취향 분석, 관리자 선곡/수집/분석 관제, 인증/데이터 경계, 배포/검증을 확인한다. 계획만 있는 기술·일반화되지 않은 하이브리드 성과는 구현·운영 범위를 구분한다.
- 실제 참여 기간/참여율은 사용자에게 확인한다. 게시에 필요한 화면 이미지는 개인 연락처·비밀값·내부 환경 정보가 드러나지 않게 제품 본문을 캡처한다. 표지/이미지/플러스 배경·성과·단계·핵심 기능을 작성한다.

## 검증 기준

- C1: 주요 기능과 기술 문구 각각에 저장소 경로 또는 실제 로드한 화면 근거가 있고, 실제 미구현/제한 운영을 과장하지 않는다. 두 사용자 제공 URL을 등록한다.
- C2: 필수 항목, 본문, 이미지, 배경·성과·진행 단계·핵심 기능이 입력/저장 후 다시 조회한 내용과 일치한다. 입력 길이/저장 오류가 없고 새 상세 URL을 확보한다.
- C3: 등록 전 목록 세 항목과 등록 후 목록을 대조해 기존 세 제목을 모두 보존하고 Music Pie가 하나 추가된 총 네 항목을 확인한다. 결과 화면을 저장한다.

첫 전체 검증의 FAIL/UNVERIFIED 합계가 3개 이상이면 최초 실패 계층을 보고하고 개별 수정을 중단한다. 2개 이하이면 원인을 수정하고 모든 기준을 다시 검증한다. 필수 미검증이 있으면 완료라고 보고하지 않는다.

## 관리자 화면 보강

사용자가 관리자 화면을 열고 실제 사용 범위를 상단 네 메뉴(`EMS Overview`, `EMS`, `화면 관리`, `추천·취향`)로 확인했다. 해당 메뉴의 실제 하위 기능을 읽고 개인 식별값과 하단 템플릿 메뉴가 드러나지 않는 제품 본문 이미지를 추가한다. 기존 등록 항목 318670을 수정해 추가하며 새 포트폴리오를 중복 생성하지 않는다. C1은 네 메뉴 범위와 본문·캡션 일치, C2는 추가 이미지와 갱신된 모든 필드의 저장 후 재조회 일치, C3은 기존 세 항목과 총 네 개 유지 및 결과 화면으로 다시 검증한다.

## 핵심 기능 카드 이미지 누락 수정

사용자 첨부 화면과 수정 폼에서 핵심 기능 다섯 카드의 이미지가 각각 0/3임을 확인했다. 프로젝트 상세 이미지와 핵심 기능 이미지는 별도 등록 항목인데 후자를 누락한 것이 원인이다. 기존 실제 화면을 각 기능에 연결하여 등록한다.

- K1: 공개 상세의 핵심 기능 다섯 카드가 기본 이미지 없이 실제 업로드 이미지로 로드된다. 이미지 URL·자연 크기와 시각 증거를 확인한다.
- K2: 기존 텍스트 51개 필드, 상세 이미지 10장, 표지·참여 정보가 저장 후 보존된다.
- K3: 동일 포트폴리오 318670을 수정하고 기존 세 항목과 총 네 개를 보존한다.
