# EMS 메타데이터·통계 계획

## 목적

관리자가 EMS 활성 트랙의 MusicBrainz 태그, 발매 시기와 EMS 유입 시기를 한 화면에서 확인한다. 원천에 값이 없는 곡은 추정하지 않고 누락률을 표시한다.

## 데이터 기준

- `ems_tracks.first_seen_at`: EMS 유입일. 발매일과 구분한다.
- MusicBrainz 녹음 태그와 최초 발매일: 공식 스냅샷에서 ISRC와 녹음 정보를 대조한 뒤 저장한다.
- 같은 ISRC의 여러 TIDAL 에디션이 하나의 MusicBrainz 녹음에 대응할 수 있으므로 태그 대조용 MBID는 `mb_tag_recording_mbid`에 별도 저장한다.
- TIDAL 앨범 발매일과 사용한 원천 메타데이터: 카탈로그 응답에서 수집해 별도 저장한다.
- MusicBrainz 전체 스냅샷 원본은 서버의 검증된 아카이브에 유지한다. 사용자별 라이브러리 데이터는 공용 EMS 통계에 사용하지 않는다.
- MusicBrainz 태그는 `mbdump-derived.tar.bz2`에 포함되며 CC BY-NC-SA 3.0이다. 화면에 출처와 라이선스를 표시하고 상업적 이용 여부는 별도로 확인한다.

## 순서

1. EMS 메타데이터 스키마와 수집 경로 확장. 기존 수집 상태와 저장값을 보존한다.
2. 관리자 전용 통계 API. 활성 트랙, 태그, 발매 시기, 유입 시기, 각 항목의 누락 수를 집계한다.
3. EMS 메뉴에 통계 화면과 그래프를 추가한다. 모바일·빈 데이터 상태를 처리한다.
4. 기존 스냅샷으로 가능한 값 백필. 원천에 없는 값은 미상으로 유지한다.
5. build·lint·DB 집계·공개 화면 확인. 수집 작업의 재시작·중단 여부를 기록한다.

## 완료 기준

- 관리자만 통계 API를 읽는다.
- 태그·발매일·유입일 각각의 기준과 누락 수가 화면에 보인다.
- 통계의 활성 트랙 합계가 DB와 일치한다.
- 새로 매칭된 EMS 트랙의 사용 가능한 원천 메타데이터가 보존된다.
