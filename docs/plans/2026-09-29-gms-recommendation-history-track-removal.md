# GMS 추천 이력 트랙 삭제 계획

## 목표

`/gms/history`에서 사용자가 개별 추천 트랙을 삭제할 수 있게 한다. 삭제는 사용자에게 보이는 추천 이력에서만 해당 트랙을 숨기며, 한 번 추천한 트랙을 다시 추천하지 않는 기존 규칙과 추천 근거의 추적 가능성은 유지한다.

## 동작 기준

- 삭제 요청은 로그인한 사용자가 소유한 추천 배치와 그 배치에 포함된 트랙에만 적용한다.
- 추천 배치의 원본 스냅샷, 노출 이력, 선호 액션 기록은 삭제하지 않는다.
- 삭제한 트랙은 추천 후보로 복귀하지 않는다.
- 같은 삭제 요청은 여러 번 호출해도 성공하는 멱등 동작으로 처리한다.
- 다른 사용자의 추천 이력과 EMS 원본 카탈로그에는 영향을 주지 않는다.

## 변경 순서

1. 사용자 화면에서 숨긴 배치별 트랙을 기록하는 DB migration과 rollback을 추가한다.
2. 추천 이력 조회에서 해당 사용자의 숨김 기록을 제외하고, 사용자 소유권을 검증하는 저장 함수를 추가한다.
3. 인증된 `DELETE /api/recommendations/history` API를 추가한다.
4. 추천 이력의 각 트랙에 삭제 버튼, 확인 대화상자, 처리·오류 상태를 추가한다.
5. 저장소·API·UI 회귀 테스트와 migration 왕복 검증을 추가한다.
6. 관련 테스트, 전체 Web 테스트, lint, build를 실행하고 결과를 변경 기록과 현재 개발 맥락에 남긴다.

## 완료 기준

- 사용자가 본인 추천 이력의 트랙을 삭제하면 새로고침 뒤 목록에서 사라진다.
- 삭제 뒤에도 추천 스냅샷과 노출 이력이 남아 같은 트랙이 다시 추천되지 않는다.
- 다른 사용자 또는 배치에 없는 트랙은 삭제할 수 없다.
- 키보드로 삭제 버튼을 사용할 수 있고 처리 중 중복 요청이 차단되며 오류가 안내된다.
- migration 적용·rollback·재적용과 관련 테스트, lint, build가 성공한다.

## 검증 계획

- 저장소 단위 테스트: 사용자 격리, 숨김 제외, 빈 배치, 멱등 삭제.
- API 단위 테스트: 인증, UUID 검증, 성공, 미소유/미존재, DB 실패.
- UI 단위 테스트: 확인 취소, 성공 후 갱신, 처리 중 상태, 실패 안내.
- migration 격리 적용·rollback·재적용.
- `apps/web` 전체 테스트, lint, production build.
- 모바일 폭의 이력 화면과 삭제 버튼의 접근 가능한 이름을 비파괴 방식으로 확인한다.
