# 멜론 100곡 단위 자동 이어 수집

## 목표

- 멜론 목록 조회를 최대 100곡씩 묶는다. 한 묶음의 TIDAL 후보 처리가 끝나면 다음 묶음을 자동 예약한다.
- 묶음 사이에는 60초 간격을 둔다. 기존 멜론 요청 최소 3초·TIDAL 요청 간격·429 대기는 유지한다.
- 현재 실행 중인 작업의 장르·페이지 위치와 원천곡을 보존한다. 이전 방식에서 남은 후보를 먼저 처리한다.
- 관리자는 현재 묶음 발견곡, 대기 후보, 다음 묶음 시각을 볼 수 있다.

## 변경 순서

1. `019_ems_melon_batches.sql`에 묶음 발견 수와 다음 묶음 시각을 추가한다. 기존 열린 작업은 발견 수 100으로 초기화해 새 페이지 조회 전에 누적 대기 후보를 처리한다.
2. 워커는 최대 50곡짜리 페이지 두 개를 읽고 후보 처리가 끝날 때까지 다음 페이지 조회를 막는다. 장르 마지막 페이지가 100곡 미만이면 그 지점에서 묶음을 닫는다.
3. 묶음 종료 후 60초 대기한 다음 저장된 장르·페이지 위치에서 다시 시작한다. 일시정지·429·접근 차단 처리는 기존 규칙을 따른다.
4. 관리자 API와 화면에 묶음 진행률·대기 후보·다음 조회 시각을 표시한다.
5. Python 구문, Web·관리자·워커 이미지 빌드, diff를 확인한다. 운영 DB 백업 후 migration·이미지 전환·상태 확인을 수행한다.

자동 테스트 추가·실행은 현재 요청 범위에 넣지 않는다.
