# GMS 엔터티별 레이아웃

## 목표

- GMS의 개별 트랙 추천을 카드 rail이 아닌 세로 목록으로 표시한다.
- 플레이리스트와 앨범은 기존 카드형 표현 원칙을 유지한다.
- 재생, 추천 수락, 싫어요, MMS 좋아요 동작과 사용자별 결정 경계를 보존한다.

## 확인된 범위

- 현재 GMS 추천 API와 화면 계약은 `Track[]`만 제공한다.
- 이번 변경에서 존재하지 않는 앨범·플레이리스트 추천 데이터를 만들거나 DB/API 계약을 확장하지 않는다.
- 실제 앨범·플레이리스트 엔터티가 GMS에 추가될 때는 카드형 컬렉션 컴포넌트로 연결한다.

## 구현 순서

1. GMS 트랙이 카드가 아닌 목록 행으로 렌더링되는 회귀 테스트를 추가한다.
2. 행 재생이 GMS 추천 전체를 대기열로 설정하는 테스트를 추가한다.
3. 데스크톱에서는 곡명·아티스트·앨범·결정 액션을 열로, 모바일에서는 메타데이터와 액션을 줄바꿈해 배치한다.
4. 집중 테스트, 변경 파일 lint, production build와 desktop/mobile browser QA를 수행한다.
5. 커밋·push 뒤 Web만 배포하고 기존 EMS container와 사용자 데이터를 보존한다.

## 완료 기준

- GMS 트랙 카드와 가로 rail이 제거되고 트랙 수만큼 목록 행이 표시된다.
- 각 행의 재생·추천 수락·싫어요·좋아요가 키보드와 포인터로 접근 가능하다.
- 트랙 재생 시 GMS 전체 추천 대기열과 선택 트랙이 함께 설정된다.
- `390x844`와 desktop에서 텍스트·액션이 겹치지 않는다.
- 비밀값, token, cookie, signed URL과 raw query를 출력하거나 기록하지 않는다.
- DB write, 추천 결과 변경, EMS worker 재시작은 없다.

## 롤백

- 배포 전 release와 Web image를 별도 식별자로 보존한다.
- 문제가 생기면 이전 image와 release symlink로 Web만 복원한다.
