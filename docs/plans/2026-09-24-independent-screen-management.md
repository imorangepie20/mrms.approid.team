# 메인·EMS 화면 독립 관리 계획

## 목표와 결정

- 관리자 사이드바에 `화면 관리`를 별도로 두고 `메인 화면`, `EMS 화면`으로 이동한다.
- 기존 에디토리얼 섹션의 제목·설명·순서·노출을 화면별로 독립 편집한다. 곡 소속과 카탈로그는 공유한다.
- 기존 사용자 화면은 배포 직후 같은 섹션을 같은 순서로 보여준다. 메인은 상위 3개, EMS는 최대 5개를 유지한다.
- 관리자 `EMS` 메뉴에는 트랙 품질·수집·정기 수집만 남긴다. 이전 `/admin/ems/sections` 주소는 새 EMS 화면 관리 주소로 연결한다.

## 변경 순서

1. `013_ems_screen_sections.sql`과 down migration: 화면별 설정을 기존 섹션에서 복사한다. 새 섹션이 생기면 EMS에는 기존 기본값을, 메인에는 비노출 기본값을 만든다.
2. 공개 섹션 API·클라이언트: 메인과 EMS가 `screen` 값을 명시하고 해당 화면 설정만 읽는다. 기존 기본 요청은 EMS로 해석한다.
3. 관리자 저장소·API: 화면별 섹션 조회와 수정. 기존 `/api/admin/ems/sections`는 EMS 설정에 연결한다. 관리자 인증과 PATCH 입력 검증을 유지한다.
4. 관리자 화면·메뉴: 공통 편집 컴포넌트를 두 화면의 서로 다른 데이터로 사용한다. 현재 화면과 실제 공개 화면 링크를 표시한다.
5. 빌드·린트·diff 검사 후 운영 DB 백업, migration, Web 교체, 화면과 공개 API·건강 상태를 확인한다. 자동 테스트는 요청되지 않아 추가·실행하지 않는다.

## 완료 기준

- 메인 설정 변경이 EMS 응답을 바꾸지 않고, EMS 설정 변경이 메인 응답을 바꾸지 않는다.
- 기존 편집 값과 공개 화면 순서는 migration 직후 유지된다.
- 새 섹션과 정기 수집이 기존 데이터 경로를 유지한다.
- 비로그인 관리자 API는 거부된다.
