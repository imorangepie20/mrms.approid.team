# 관리자 홈·EMS 선곡 갱신 기능

## 요청과 확인한 선곡 기준

- 관리자가 이번 홈·EMS 노출 트랙 갱신을 관리자 화면에서 실행할 수 있게 한다.
- TIDAL 공개 EDITORIAL 플레이리스트의 원본 분류를 사용한다. 신곡은 원본 플레이리스트 최근 수정 시각, 인기도, 원래 곡 순서를 사용하며 나머지는 원본 팔로워 수, 곡 인기도, 순서를 사용한다.
- 개인화 추천이나 멜론 수집 순서와 별개다. 신곡 정렬의 최근 수정 시각은 트랙 발매일과 다르다.
- 기존 EMS 활성 트랙 중 ISRC 또는 TIDAL ID로 연결하고 최신 KR STREAM 재생 가능, 30초 이상 조건을 적용한다. 섹션당 최대 12곡, 섹션 간 중복 제거를 유지한다.

## 설계와 의존 순서

1. `033_ems_editorial_refresh_jobs.sql`: 미리보기 요청·처리 상태, 선택 결과, 변경 전 snapshot, 생성 관리자, 30분 유효 기간과 적용 결과를 저장한다. 진행 중 요청 중복은 DB unique index로 차단한다.
2. Python 기존 선곡 projection을 재사용하는 미리보기 worker를 추가한다. TIDAL 요청은 API 요청 밖의 기존 EMS worker에서 budget 24·timeout 8초·playlist 2개 범위로 수행한다. 관리자 수집 루프 중에도 미리보기 작업에 실행 기회를 제공한다.
3. 관리자 전용 API: 목록/미리보기 생성과 확인 후 적용. 적용은 외부 조회 없이 저장된 미리보기 ID만 받고, 최신 재생 조건·기존 membership·유효 기간·상태를 재검증한 뒤 단일 DB transaction으로 교체한다. 불일치·부족·오류 시 기존 선곡을 보존한다.
4. 관리자 메인/EMS 화면 관리에 공통 패널을 추가한다. 기준 설명, 섹션별 추가·제외·후보 곡/원본, 대기/완료/실패, 마지막 적용 시각을 표시한다. 기존 HUD 색상과 Headless UI 커스텀 확인창을 사용한다. 적용이 홈·EMS 양쪽에 반영됨을 명시한다.
5. 화면별 제목·설명·순서·노출과 사용자 개인 데이터를 보존한다. 기준 편집·자동 주기·수동 곡 지정을 이번 기능에 추가하지 않는다.
6. 직접 회귀 및 격리 PostgreSQL 검증 후 운영 backup·migration·Web/EMS 이미지 교체, 실제 관리자 미리보기/적용을 확인한다.

## 객관적 완료 검증

- C1: 기존 선곡 순위/중복 제거 회귀와 KR STREAM 최신 상태 제외 테스트 통과. 화면 기준 문구를 실제 source와 대조한다.
- C2: 격리 PostgreSQL에서 migration up/down/reapply, 미리보기 선곡 쓰기 0, 저장 미리보기 그대로 적용, 부족/만료/동시 요청/중간 실패/재생 불가/기존 목록 변경 시 선곡 보존과 화면·개인 데이터 불변을 확인한다.
- C3: 관리자 API 테스트로 인증·권한·origin·엄격한 입력·존재하지 않는 ID·상태 충돌 및 중복 적용을 검증한다.
- C4: 실제 관리자 화면에서 미리보기→커스텀 확인 취소→적용, 대기/완료 상태, 키보드 Escape·포커스와 모바일 표시를 확인한다.
- C5: 관련 Web/Admin 테스트, Python worker 회귀, Web/Admin lint·타입/build 및 diff check 통과.
- C6: 운영 backup 읽기·migration·이미지 revision·readiness 및 비로그인 차단, 관리자 미리보기/적용과 공개 홈/EMS 목록 일치, 개인 데이터·독립 화면 설정 보존과 Melon 수집 지속을 확인한다.

첫 전체 검증에서 FAIL/UNVERIFIED 합계가 3개 이상이면 개별 증상 수정 대신 최초 실패 계층을 보고한다. 2개 이하이면 원인 수정 후 전체 검증을 다시 실행한다. 필수 미검증이 있으면 완료로 보고하지 않는다.
