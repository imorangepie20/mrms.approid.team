# Music Pie 사용자 경험 스토리보드 설계

**목표:** 비로그인 탐색부터 TIDAL 연결, 개인화 추천, GMS 의사결정, MMS 관리까지 일관된 음악 추천 경험을 정의한다.

**범위:** 사용자용 웹·앱 화면의 정보 구조와 상호작용. 관리자 화면, API·데이터베이스 구현, 실제 TIDAL 재생 권한 세부 사항은 포함하지 않는다.

## 설계 원칙

- 고급스럽고 간결하되, 최신 음악·플레이리스트·앨범 아트를 충분히 노출해 화면이 비어 보이지 않게 한다.
- 같은 정보 구조를 유지하면서 데스크톱은 탐색 그리드, 모바일은 카드와 미니 플레이어에 맞춰 적응한다.
- 사용자의 재생 상태는 화면 이동 후에도 유지한다.
- 개인화가 필요한 기능은 로그인 후에만 제공하고, 비로그인 사용자는 서비스의 공개 탐색 가치를 먼저 경험한다.

## 정보 공간

| 공간 | 역할 | 사용자 노출 |
|---|---|---|
| EMS | 외부 플랫폼과 사용자 플레이리스트에서 도입한 전체 트랙·플레이리스트 후보 | 공개 탐색, 최신곡, 최신 플레이리스트, 플랫폼별 컬렉션 |
| GMS | 특정 사용자에게 추천해 의사결정을 기다리는 트랙·플레이리스트 | 로그인 사용자에게 개인화 추천으로 노출 |
| MMS | 사용자의 취향이 확정된 개인 음악 공간 | 로그인 사용자에게 내 음악으로 노출 |

사용자가 GMS의 트랙을 선호하면 MMS에 추가한다. 좋아하지 않음으로 결정하면 그 트랙은 해당 사용자의 MMS와 이후 GMS 추천 후보에서 영구 제외한다. 이 결정은 다른 사용자와 EMS 원본 카탈로그에는 영향을 주지 않는다.

## 전역 레이아웃

### 데스크톱

- 상단에는 브랜드, 탐색, 검색, 내 음악, 사용자 메뉴를 둔다.
- 메인 영역은 가로 스크롤 가능한 앨범·플레이리스트 행과 트랙 목록으로 구성한다.
- 하단 고정 플레이어에는 앨범 아트, 트랙·아티스트명, 이전·재생·다음, 재생 위치, 대기열 진입을 둔다.

### 모바일

- 핵심 탐색 영역을 카드 중심으로 재배치하고, 중요하지 않은 보조 정보는 상세 화면으로 이동한다.
- 하단에는 홈·탐색·내 음악 중심의 탐색 제어와 현재 재생 중인 미니 플레이어를 둔다.
- 미니 플레이어를 탭하면 전체 화면 플레이어를 연다.

## 화면 스토리보드

### 1. 비로그인 홈

**목적:** 로그인 전에 EMS의 음악 탐색 가치를 보여주고, 개인화가 필요한 순간에 TIDAL 연결을 유도한다.

1. 최신곡, 최신 플레이리스트, 플랫폼별 플레이리스트를 우선 노출한다.
2. 앨범 아트와 음악 관련 배경 이미지를 사용해 탐색 밀도를 높인다.
3. 공개 재생 또는 미리듣기 가능 범위는 실제 TIDAL 권한·약관 확인 결과를 따른다.
4. 저장, 좋아요, MMS 추가, GMS 개인화 추천 같은 행동은 로그인 안내를 연다.
5. 로그인 안내의 주요 행동은 `내 취향으로 추천받기`다.

### 2. TIDAL 온보딩

**목적:** 사용자가 어떤 데이터를 개인화 시작점으로 사용할지 이해하고 선택한다.

1. **TIDAL 연결:** 연결 목적과 가져올 데이터의 범위를 짧게 설명하고 연결을 시작한다.
2. **플레이리스트 선택:** 사용자는 가져올 플레이리스트를 하나 이상 선택한다.
3. **MMS 생성·추천 시작:** 선택한 트랙으로 초기 MMS와 사용자 취향 벡터를 만들고, 첫 개인화 추천으로 이동한다.

연결·가져오기 실패 시에는 실패 원인과 재시도 행동을 같은 화면에 표시한다. 사용자는 공개 탐색으로 돌아갈 수 있다.

### 3. 로그인 사용자 메인

**목적:** 탐색 중심의 풍부한 홈에서 개인화 추천으로 자연스럽게 이동시킨다.

노출 순서:

1. 최신곡
2. 최신 플레이리스트
3. 플랫폼별 플레이리스트
4. 사용자를 위한 추천 트랙과 추천 플레이리스트
5. 이어 듣기 또는 최근 재생 항목

각 행의 트랙·앨범·플레이리스트는 카드에서 바로 재생할 수 있다. 추천 섹션은 GMS로 이동하는 진입점이다.

### 4. GMS 추천 화면

**목적:** 추천 트랙을 들은 뒤, 선호 여부를 명시적으로 수집한다.

- 트랙 카드에는 앨범 아트, 곡명, 아티스트, 재생 행동을 표시한다.
- `MMS에 담기`는 트랙을 MMS에 추가하고 해당 사용자의 취향 갱신 이벤트를 남긴다.
- `다시 추천하지 않기`는 영구 제외의 영향을 설명한 뒤 확정한다.
- 영구 제외 후에는 즉시 되돌릴 수 있는 안내를 제공하고, 설정·내 음악에서 나중에 제외 목록을 관리할 수 있는 경로를 둔다.
- 모든 액션은 키보드와 터치로 동등하게 수행할 수 있어야 한다.

### 5. MMS 내 음악

**목적:** 사용자의 초기 TIDAL 플레이리스트와 선호 확정 트랙을 한 공간에서 관리한다.

- 초기에는 선택한 TIDAL 플레이리스트를 기준으로 구성한다.
- GMS에서 선호한 트랙과 플레이리스트는 MMS에 추가한다.
- 추천 또는 사용자 행동에 따른 추가·제거 결과를 최근 변경 정보로 보여준다.
- 영구 제외한 트랙은 일반 MMS 목록에 보이지 않으며, 별도 관리 화면에서만 복구할 수 있다.

### 6. 전체 화면 플레이어

**목적:** 탐색을 방해하지 않으면서 필요할 때 몰입형 재생을 제공한다.

- 큰 앨범 아트, 트랙 정보, 재생 제어, 재생 위치, 대기열을 표시한다.
- 닫으면 이전 탐색 화면과 재생 상태로 돌아간다.
- 다음·이전 트랙과 대기열 변경은 고정 하단 플레이어와 동기화한다.

## 상태와 피드백

| 상황 | 사용자에게 보이는 결과 |
|---|---|
| 비로그인 사용자가 개인화 기능 선택 | 기능 목적을 설명하고 TIDAL 연결 행동을 제공 |
| 플레이리스트 가져오는 중 | 진행 상태와 취소 또는 재시도 가능 여부 표시 |
| 추천 없음 | 새로운 플레이리스트를 가져오거나 공개 탐색을 계속할 수 있게 안내 |
| 영구 제외 확정 | 해당 사용자에게 다시 추천하지 않는다는 결과와 즉시 되돌리기 제공 |
| 재생 불가 | 재생 불가 이유와 가능한 다음 행동 표시 |

## 접근성·반응형 기준

- 아이콘만 있는 재생·선호·제외 버튼에는 접근 가능한 이름을 제공한다.
- 터치 대상은 충분한 크기와 간격을 유지한다.
- 키보드로 재생 제어, GMS 선호·제외, 로그인 안내를 조작할 수 있다.
- 텍스트와 배경·앨범 아트 위 오버레이의 대비를 유지한다.
- 좁은 화면에서는 고정 플레이어와 탐색 메뉴가 콘텐츠를 가리지 않게 안전 영역을 확보한다.

## 수용 기준

- 비로그인 사용자는 EMS 탐색을 이용하고 개인화 행동에서 로그인 안내를 받는다.
- 로그인 사용자는 TIDAL 플레이리스트를 선택해 MMS와 개인화 추천을 시작할 수 있다.
- 모든 트랙 화면에서 재생을 시작하고, 페이지 이동 후에도 재생 상태가 유지된다.
- GMS에서 선호는 MMS 추가로, 비선호는 해당 사용자에 대한 영구 추천 제외로 반영된다.
- 메인 화면은 최신곡·최신 플레이리스트·플랫폼별 플레이리스트·개인화 추천을 모두 제공한다.
