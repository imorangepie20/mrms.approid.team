# EMS 관리자 페이지 설계

## 상태

- 설계 승인: 사용자 승인 완료
- 대상 주소: `https://mrms.approid.team/admin`
- 범위: EMS 카탈로그 운영 현황 조회와 편집
- 제외: `hud.approid.team` 배포, 수집 재실행, 대량 삭제, 신규 수집 파이프라인

## 목표

운영자가 EMS의 카테고리와 트랙 상태를 한 화면에서 확인하고, 메인/EMS에 노출되는 카테고리 메타데이터를 안전하게 수정할 수 있게 한다. 사용자 서비스의 추천·재생 흐름과 관리자 기능을 같은 origin에서 유지해 인증과 배포 경계를 단순하게 한다.

## 구성

### 관리자 프런트엔드

- `C:\Wspace\hud-admin-template`의 React/Vite/TypeScript/Tailwind 구성과 시각 자산을 재사용한다.
- 관리자 프런트엔드의 공개 경로는 `/admin`으로 고정한다.
- 브라우저는 상대 경로로 `/api/admin/ems/*`를 호출한다. 별도 관리자 도메인이나 CORS 설정은 추가하지 않는다.
- 인증 여부를 화면에서 표시할 수 있지만, 화면의 조건부 렌더링은 보안 경계가 아니다.

### 관리자 API

기존 Next.js 애플리케이션의 서버 API로 구현한다.

- `GET /api/admin/ems/summary`
  - 전체 활성 트랙 수, 활성 섹션 수, artwork 누락 수, 임베딩 상태별 수, 최근 ingest 상태를 반환한다.
- `GET /api/admin/ems/sections`
  - 섹션별 slug, 제목, 설명, 순서, 활성 상태, 트랙 수, 수정 시각을 반환한다.
- `PATCH /api/admin/ems/sections/:id`
  - `title`, `description`, `sortOrder`, `active`만 수정한다.
  - `slug`와 식별자는 수정할 수 없다.
  - 정수 순서와 문자열 길이를 서버에서 검증한다.
- `GET /api/admin/ems/tracks`
  - 제목·아티스트·앨범 검색과 페이지네이션을 지원한다.
  - artwork, TIDAL ID, 재생 가능 여부, 섹션 소속, 임베딩 상태를 반환한다.
  - 검색어와 페이지 크기는 상한을 둔다.
- `GET /api/admin/ems/ingest-runs`
  - ingest 실행 시각, 상태, 후보·매칭·중복·실패·대기 통계와 오류 요약을 반환한다.
  - 현재 스키마에 별도 `duplicate` 상태가 없어 모호 매칭(`ambiguous`)을 운영상 중복 검토 수치로 표시한다.

1차에서는 `POST` 재실행과 `DELETE` 대량 삭제 API를 만들지 않는다.

## 인증과 권한

- 서버는 기존 Auth0 세션에서 `user.sub`를 읽는다.
- `ADMIN_AUTH0_SUBJECTS` 환경변수를 쉼표 또는 공백으로 분리해 허용 subject 목록을 만든다.
- 세션이 없으면 `401`, 세션은 있지만 목록에 없으면 `403`을 반환한다.
- 허용 목록은 서버 런타임에서만 읽으며 브라우저 번들에 포함하지 않는다.
- 별도 DB 역할 테이블이나 관리자 권한 마이그레이션은 이번 범위에 포함하지 않는다.

## 데이터 경계와 동작

- 기존 EMS 테이블(`ems_editorial_sections`, `ems_track_sections`, `ems_tracks`, `ems_track_embeddings`, `ems_ingest_runs` 및 관련 가용성 테이블)만 사용한다.
- 섹션 수정은 한 번의 검증된 업데이트로 처리하고, 성공 후 다음 조회부터 메인/EMS에 반영한다.
- 트랙 조회는 현재 카탈로그·artwork·최신 재생 가능 상태·임베딩·섹션 관계를 서버에서 조합한다.
- DB 연결 정보, Auth0 토큰, 쿠키, 원시 SQL은 클라이언트로 전달하지 않는다.
- 읽기 오류와 권한 오류는 서로 다른 상태 코드와 사용자 메시지로 구분한다. 내부 오류 상세와 비밀값은 응답에 노출하지 않는다.

## 화면 범위

1. **Dashboard**: 운영 숫자와 최근 수집 상태를 요약한다.
2. **Sections**: 카테고리 메타데이터를 편집하고 트랙 수를 확인한다.
3. **Tracks**: 검색·필터·페이지네이션으로 개별 트랙의 품질 상태를 확인한다.
4. **Ingestion**: 수집 실행의 결과와 실패 원인을 확인한다.

파괴적인 작업과 수집 제어는 이후 별도 승인으로 추가한다.

## 검증 기준

- 허용되지 않은 사용자로 관리자 API에 접근하면 `403`이 반환된다.
- 로그인하지 않은 요청은 `401`이 반환된다.
- 허용된 사용자는 `/admin`을 열고 네 화면의 데이터를 조회할 수 있다.
- 섹션 수정의 허용 필드와 유효성 검사가 서버에서 적용된다.
- 수정된 섹션은 사용자용 메인/EMS 조회에 반영된다.
- 트랙 검색 결과에 artwork·재생 가능 여부·임베딩·섹션 정보가 표시된다.
- `/admin` 빌드와 기존 사용자 경로 빌드가 모두 성공한다.
- 기존 사용자 인증·재생·추천 API에 회귀가 없다.

## 구현 순서

1. 관리자 인증 가드와 API 공통 응답 형식을 추가한다.
2. EMS 요약·섹션·트랙·ingest 조회 API를 추가한다.
3. 섹션 수정 API와 입력 검증을 추가한다.
4. 관리자 프런트엔드를 `/admin`에 연결한다.
5. 인증·API·빌드·라우팅 회귀 검증을 실행한다.
