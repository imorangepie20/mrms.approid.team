# EMS 관리자 페이지 구현 계획

> **실행 규칙:** 이 계획은 사용자 승인된 설계 문서(`docs/superpowers/specs/2026-09-23-ems-admin-design.md`)를 구현하기 위한 작업 순서다. 각 단계는 실패 테스트 또는 재현 가능한 검증을 먼저 확보한 뒤 구현한다.

## 목표

`https://mrms.approid.team/admin`에서 Auth0 허용 사용자만 EMS 카탈로그 상태를 조회하고, 카테고리 메타데이터를 수정할 수 있게 한다. 기존 사용자용 Next.js 경로와 TIDAL·추천·재생 기능은 유지한다.

## 제약과 결정

- `hud.approid.team`에는 배포하지 않는다. `C:\Wspace\hud-admin-template`은 UI·런타임 참고 및 복사 원본으로만 사용한다.
- 관리자 API는 기존 Next.js 서버가 제공하고, 관리자 UI는 템플릿의 Vite 빌드 산출물을 `/admin`에서 제공한다.
- `ADMIN_AUTH0_SUBJECTS`는 서버 전용 환경변수다. UI에서 권한을 판정하지 않는다.
- 1차에는 수집 재실행, 대량 삭제, 신규 DB 역할 테이블, 감사 로그를 추가하지 않는다.
- 모든 DB 쿼리는 파라미터 바인딩을 사용하고 검색·페이지 크기에 상한을 둔다.

## 변경 파일 예상

- 추가: `apps/admin/` (템플릿 기반 Vite 관리자 앱)
- 추가: `apps/web/src/lib/auth/admin.ts` 및 테스트
- 추가: `apps/web/src/lib/ems/admin.ts` 및 테스트
- 추가: `apps/web/src/app/api/admin/ems/{summary,sections,sections/[id],tracks,ingest-runs}/route.ts` 및 테스트
- 추가: `apps/web/src/app/admin/[[...slug]]/page.tsx` (Vite 산출물 셸)
- 수정: `apps/web/package.json`, `apps/web/Dockerfile`, 필요한 빌드 설정·환경변수 예시
- 수정: `docs/overview/current-development-context.md`, 변경 기록 문서

### Task 1: 관리자 빌드 경계와 `/admin` 라우팅 고정

**목적:** 별도 도메인 없이 Next.js 서버가 Vite 산출물을 같은 origin의 `/admin`에서 제공하게 한다.

**파일:**

- 추가 `apps/admin/package.json`, `vite.config.ts`, `tsconfig*.json`, `src/main.tsx`, `src/App.tsx`, `src/index.css`
- 추가 `apps/web/src/app/admin/[[...slug]]/page.tsx`
- 수정 `apps/web/Dockerfile`, `apps/web/package.json`

- [ ] 템플릿의 레이아웃·테마·공통 컴포넌트를 `apps/admin`으로 복사하고 의존성을 고정한다. 원본 템플릿의 배포 도메인(`hud.approid.team`)과 예제 인증 화면은 복사하지 않는다.
- [ ] Vite `base`를 `/admin/`으로 설정하고 산출물 파일명을 고정해 Next 셸이 참조할 JS/CSS 경로를 안정화한다.
- [ ] React Router에 `/admin`, `/admin/sections`, `/admin/tracks`, `/admin/ingestion`을 등록하고 basename을 `/admin`으로 설정한다.
- [ ] Next catch-all 페이지는 관리자 root element와 `/admin/assets/*` 정적 파일만 제공한다. 관리자 API 요청이나 DB 접근은 수행하지 않는다.
- [ ] Docker build에서 관리자 의존성 설치·Vite build를 먼저 수행해 `apps/web/public/admin`에 산출물을 만들고, 기존 Next standalone 복사 단계가 이를 포함하는지 확인한다.
- [ ] 실패 조건: `/admin`이 200이 아니거나 `/admin/sections` 새로고침 시 사용자 홈으로 전환되면 다음 작업으로 진행하지 않고 라우팅을 먼저 수정한다.

검증:

```powershell
npm --prefix apps/admin run build
npm --prefix apps/web run build
```

### Task 2: Auth0 관리자 가드

**목적:** 모든 관리자 API에서 동일한 서버 권한 검사를 사용한다.

**파일:**

- 추가 `apps/web/src/lib/auth/admin.ts`, `admin.test.ts`
- 수정 `apps/web/.env.example`

- [ ] `ADMIN_AUTH0_SUBJECTS`를 쉼표·공백 기준으로 정규화하는 순수 함수를 작성한다. 빈 값은 허용 사용자 없음으로 처리한다.
- [ ] 기존 `requireAuth0Subject()`를 재사용해 `requireAdminAuth0Subject()`를 구현한다.
- [ ] 세션 없음은 `401`, 세션은 있으나 allowlist 불일치는 `403`으로 변환할 수 있는 타입화된 오류를 만든다.
- [ ] subject 값이나 환경변수 전체를 로그·응답에 포함하지 않는다.
- [ ] 테스트: 세션 없음, allowlist 빈 값, 허용 subject, 비허용 subject, 공백·중복 파싱을 검증한다.

검증:

```powershell
npm --prefix apps/web test -- src/lib/auth/admin.test.ts
```

### Task 3: EMS 관리자 조회·수정 저장소

**목적:** API가 사용할 DB 조회와 섹션 수정의 데이터 매핑을 한 곳에 둔다.

**파일:**

- 추가 `apps/web/src/lib/ems/admin.ts`, `admin.test.ts`

- [ ] summary 쿼리로 활성 트랙·활성 섹션·artwork 누락·임베딩 상태별 집계·가장 최근 ingest를 반환한다.
- [ ] sections 쿼리로 섹션 메타데이터와 활성 트랙 수를 반환한다.
- [ ] tracks 쿼리는 제목·artist·album 검색, `status`·`embeddingStatus` 필터, 정렬, 제한된 cursor/offset 페이지네이션을 지원한다. 최신 지역 STREAM availability를 별도 lateral 조회로 계산한다.
- [ ] tracks 결과에는 TIDAL ID, artwork URL, playback 가능 여부, section membership, embedding 상태를 포함한다.
- [ ] ingest-runs 쿼리는 실행 상태와 통계·안전한 오류 요약만 반환하고 원시 provider 응답은 제외한다.
- [ ] 섹션 PATCH는 허용 필드만 검증한 뒤 `ems_editorial_sections`를 한 번 업데이트한다. `slug`·id는 변경하지 않으며 `sort_order >= 0`, 문자열 길이 상한을 적용한다.
- [ ] 테스트는 실제 DB 없이 `QueryExecutor` mock으로 SQL 값·매핑·빈 결과·잘못된 입력을 검증한다.

검증:

```powershell
npm --prefix apps/web test -- src/lib/ems/admin.test.ts
```

### Task 4: 관리자 EMS API route handlers

**목적:** 인증, 입력 검증, 저장소, 오류 응답을 HTTP 계약으로 연결한다.

**파일:**

- 추가 `apps/web/src/app/api/admin/ems/summary/route.ts` 및 테스트
- 추가 `apps/web/src/app/api/admin/ems/sections/route.ts` 및 테스트
- 추가 `apps/web/src/app/api/admin/ems/sections/[id]/route.ts` 및 테스트
- 추가 `apps/web/src/app/api/admin/ems/tracks/route.ts` 및 테스트
- 추가 `apps/web/src/app/api/admin/ems/ingest-runs/route.ts` 및 테스트
- 필요 시 추가 `apps/web/src/lib/api/admin-response.ts`

- [ ] 모든 route가 admin guard를 가장 먼저 실행하도록 한다.
- [ ] query/body 파싱 실패는 `400`, 인증 실패는 `401/403`, DB 장애는 내부 코드가 노출되지 않는 `503`으로 정규화한다.
- [ ] PATCH는 JSON object인지 확인하고 허용 필드 외 입력을 거부하거나 무시하는 정책을 한 가지로 고정해 테스트한다. 이번 설계에서는 허용 필드 외 입력을 `400`으로 거부한다.
- [ ] GET tracks의 검색어·limit·cursor가 저장소 상한을 넘지 않게 하고 잘못된 cursor는 `400`으로 반환한다.
- [ ] 테스트: 각 route의 401/403, 정상 조회, 잘못된 파라미터, PATCH 성공/실패, DB 예외를 검증한다.

검증:

```powershell
npm --prefix apps/web test -- src/app/api/admin/ems
```

### Task 5: 관리자 UI 데이터 연결

**목적:** 템플릿 화면을 EMS 운영 화면으로 교체하고 API 상태를 안전하게 표시한다.

**파일:**

- 수정 `apps/admin/src/App.tsx`, 레이아웃·공통 컴포넌트
- 추가 `apps/admin/src/lib/api.ts`, `src/pages/Dashboard.tsx`, `Sections.tsx`, `Tracks.tsx`, `Ingestion.tsx`
- 추가 또는 수정 UI 테스트/fixture

- [ ] Dashboard 카드에 summary 집계와 마지막 ingest 상태를 표시한다.
- [ ] Sections 표에서 제목·설명·순서·활성 상태를 편집하고 저장 성공/실패를 명확히 표시한다. 저장 중 중복 요청을 막고 취소 시 로컬 변경을 버린다.
- [ ] Tracks 표에 검색 입력, 상태 필터, cursor 페이지네이션, artwork fallback, TIDAL ID, 재생 가능 여부, section·embedding 상태를 표시한다.
- [ ] Ingestion 표에 실행 상태와 통계를 표시하며 재실행·삭제 버튼은 넣지 않는다.
- [ ] API가 401이면 로그인 유도, 403이면 관리자 권한 없음, 503이면 재시도 안내를 표시한다. 민감한 응답 본문은 그대로 렌더링하지 않는다.
- [ ] 키보드 포커스, 표 모바일 overflow, 이미지 실패 fallback을 템플릿 스타일에 맞춰 확인한다.

검증:

```powershell
npm --prefix apps/admin run lint
npm --prefix apps/admin run build
```

### Task 6: 통합 회귀 검증과 문서화

**목적:** 새 관리자 기능이 기존 사용자 서비스·배포 경계를 깨지 않았음을 확인한다.

**파일:**

- 수정 `apps/web/Dockerfile`, 관련 build 설정
- 수정 `docs/overview/current-development-context.md`
- 추가 `docs/changes/2026-09-23-ems-admin.md`

- [ ] 관리자와 web의 lockfile·빌드 산출물이 재현 가능하고 secrets가 번들에 포함되지 않는지 확인한다.
- [ ] `npm --prefix apps/web test`, `npm --prefix apps/web run lint`, `npm --prefix apps/web run build`를 실행한다.
- [ ] 로컬 production 서버에서 `/admin`, `/admin/sections`, `/api/admin/ems/summary`를 확인한다. Auth0 미설정 환경에서는 페이지 200과 API 401/503 등 의도한 경계만 확인한다.
- [ ] 기존 `/`, `/ems`, `/search`, `/api/ems/sections` smoke를 실행한다.
- [ ] 필요하면 Docker image를 빌드해 standalone runtime에 `/public/admin`이 포함되는지 검사한다.
- [ ] 문서에 실제 성공 명령, 테스트 수치, 미검증한 운영 항목을 한국어로 기록한다. 실패한 명령은 성공으로 표시하지 않는다.
- [ ] `git diff --check`와 변경 범위 검토 후 커밋한다.

완료 기준:

- Auth0 allowlist 사용자만 관리자 API를 사용할 수 있다.
- `/admin` 네 화면이 같은 `mrms.approid.team` origin에서 로드된다.
- 카테고리 수정이 저장되고 사용자용 EMS 조회에 반영된다.
- 트랙·ingest 운영 상태가 조회된다.
- 기존 사용자 테스트·lint·build와 `/admin` 빌드가 모두 통과한다.
