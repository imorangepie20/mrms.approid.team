# 핵심 원칙

## 확인된 원칙

- 프로젝트는 TIDAL API로 사용자의 플레이리스트를 받아 취향을 분석하고 맞춤 음악을 추천한다.
- TIDAL API 접근 권한은 확보된 것으로 본다.
- 플레이리스트 접근은 사용자가 허용한 TIDAL API 권한 범위 안에서만 수행한다.
- 추천은 사용자에게 제안하는 결과이며, 입력 플레이리스트와 추천 기준을 구분해 추적 가능하게 기록한다.
- 사용자별 취향 모델은 해당 사용자의 플레이리스트 트랙과 추천 결과에 대한 액션을 학습 근거로 삼아 갱신한다.
- 개인 취향 모델과 사용자 액션 데이터는 사용자 단위로 격리하고, 사용자 간에 혼용하지 않는다.
- 사용자가 좋아하지 않음으로 판정한 트랙은 해당 사용자의 MMS와 이후 GMS 추천 후보에서 영구 제외한다. EMS의 원본 트랙은 다른 사용자를 위해 유지한다.
- 현재 구현과 런타임 설정에서 확인되지 않은 데이터 모델·배포 조건은 추정하지 않는다.
- 확인되지 않은 도메인 규칙, 권한 경계, 데이터 정합성 조건을 추정해 만들거나 변경하지 않는다.
- 외부 프로젝트·계정·데이터 저장소·배포 환경과 경계를 유지한다.
- 비밀값, 쿠키, 캐시, DB dump를 저장소에 추가하지 않는다.
- 실제 실행한 검증만 통과로 기록한다.

## 프로젝트별 확인 항목

- 도메인 불변 조건과 상태 전이
- TIDAL 인증·권한 범위와 사용자 동의 흐름
- 플레이리스트 및 취향 분석 데이터의 저장·삭제 정책
- 추천 기준, 설명 방식, 사용자 액션의 학습 반영 규칙
- 개인 취향 모델의 갱신 주기, 버전 관리, 재학습과 복구 방식
- 권한 및 최종 상태 결정 주체
- 데이터 저장소와 복구·마이그레이션 절차
- AI 기능의 사용 여부와 허용 범위
- 참조 자산의 수정·재사용 허용 범위
- 배포 대상과 다른 환경의 경계

위 항목은 코드·설정·기존 문서 또는 사용자 지시에서 확인한 근거와 함께 갱신한다.
